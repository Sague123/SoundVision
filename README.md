# SoundVision v2

Аудио-реактивная светомузыка для телевизора. Браузерная вкладка на мини-ПК,
подключённом к ТВ по HDMI: слушает **системный звук** (что угодно — Spotify,
YouTube Music, плеер, браузер), строит генеративную картинку под жанр,
тональность и транзиенты и показывает синхронизированный текст песни.

Никаких виртуальных аудиокабелей и никаких фиксированных пресетов.

---

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:5173
```

Для прода:

```bash
npm run build        # tsc --noEmit + vite build → dist/
npm run preview      # раздать dist/ по сети
```

### Захват системного звука (Windows, Chrome/Edge)

Это единственный неочевидный шаг, и от него зависит вообще всё:

1. Нажать «Запустить визуализацию».
2. В окне выбора источника перейти на вкладку **«Весь экран»** и выбрать экран.
   Захват *отдельной вкладки* даёт звук только этой вкладки — системный звук
   так не получить.
3. Включить галочку **«Также предоставить доступ к системному аудио»**.

Разрешение выдаётся на сессию, поэтому старт-экран появляется при каждом
открытии страницы — это ограничение браузера, а не недоработка.

Видео-трек глушится сразу после получения разрешения: нужен только звук.

### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `S` | панель настроек |
| `F` | полный экран |
| `R` | Reshuffle — новая стартовая точка генератора для текущего трека |
| `D` | дебаг-оверлей с сырыми числами и графиками |
| `Esc` | закрыть панель |

Курсор прячется через 2.5 секунды без движения. Пока идёт визуализация,
запрашивается wake lock, чтобы экран не гас посреди вечера.

## Как это устроено

```
звук  →  mood vector  →  генератор  →  три слоя  →  compositor  →  экран
```

### Анализ звука (`src/audio/`)

FFT 2048, обновление на каждом кадре, экспоненциальное сглаживание с
настраиваемым коэффициентом.

| Файл | Что делает |
|---|---|
| `capture.ts` | `getDisplayMedia` + `AnalyserNode`, внятные ошибки на каждый отказ |
| `features.ts` | RMS, spectral flux/centroid, ZCR, onset с адаптивным порогом, тренд энергии → `section` |
| `chroma.ts` | chroma-вектор по 12 полутонам, тональность по Krumhansl-Schmuckler |
| `beat-tracker.ts` | BPM автокорреляцией огибающей onset-силы + фаза доли |
| `mood-vector.ts` | сборка всего в один объект на кадр |

Громкость нормализуется адаптивно (убывающий пик), поэтому тихий джаз и
закомпрессированное техно одинаково живые без ручного гейна.

`section` (`buildup` / `drop` / `calm` / `steady`) считается из окна ~14 секунд:
короткое среднее против длинного плюс наклон, с гистерезисом, чтобы набор
примитивов не дёргался.

### Генеративная система (`src/render/`)

Вместо фиксированных пресетов — пул примитивов с непрерывными параметрами:

**Примитивы:** flow field (частицы в поле симплекс-шума), metaballs
(blur + contrast вместо marching squares), Voronoi (поле расстояний в низком
разрешении, 30 Гц), cellular automata (5 наборов правил, шаг привязан к темпу),
L-система (фрактальное ветвление), raymarch (WebGL2, SDF).
**Калейдоскоп** — не рисующий примитив, а модификатор: отражает N-угольной
симметрией всё, что уже нарисовано в жанровом слое.

Что делает картинку разной:

- **Seed трека** — хэш `artist + title` задаёт пул примитивов, порядок
  симметрии, сдвиг палитры, скорость морфинга и смещение рейтинга каждого
  примитива. Трек узнаваем при повторном прослушивании, но это не клип.
  Два разных трека с похожим mood vector выглядят по-разному именно из-за
  смещения рейтинга.
- **Рейтинг уместности** — каждый примитив непрерывно оценивается по текущему
  настроению; активны верхние N, где N зависит от секции (затишье — 1, дроп — 3).
- **Морфинг** — веса едут к цели экспоненциально, никаких переключений.
  Калейдоскоп вплывает через `smoothstep`, а не включается щелчком.

### Слои

1. **База** (`layer-base.ts`) — палитра и фон от тональности и энергии, один
   медленный примитив подложкой, виньетка, опционально размытая обложка.
2. **Жанр** (`layer-genre.ts`) — активный набор примитивов со следами
   (длина следа — от энергии) и калейдоскоп поверх.
3. **Транзиенты** (`layer-transient.ts`) — particle burst, shockwave,
   screen shake, strobe flash и глитч (RGB-сплит + сдвиг блоков по сведённому
   кадру).

`compositor.ts` сводит их, применяет тряску с оверскейлом (чтобы не открывались
чёрные поля), накладывает глитч и держит fps.

### Палитра

Строится непрерывно: схема (отдельные спецификации для мажора и минора) +
сдвиг от seed'а + живая модуляция энергией и яркостью тембра. Если включено
«Цвет из обложки», доминирующий оттенок обложки подмешивается тем сильнее,
чем ниже уверенность в тональности.

## Обложка трека

### Spotify

1. Завести приложение в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. В Redirect URIs указать **адрес этой страницы** (например
   `http://localhost:5173/`) — ровно тот, что показан в адресной строке.
3. В панели настроек: «Обложка и источники» → «Подключить Spotify», вставить
   Client ID.

Авторизация — Authorization Code + PKCE (client secret в браузере хранить негде),
токены в localStorage, поллинг `/me/player/currently-playing` раз в 4 секунды.
Оттуда же берутся `progress_ms` и `duration_ms` для текста песни.

### YouTube Music

Нужны две части — мост и расширение:

```bash
npm run bridge       # ws://127.0.0.1:8787, слушает только localhost
```

Расширение (`extension/`) ставится как unpacked, публикация в Chrome Web Store
не нужна:

1. `chrome://extensions` → включить «Режим разработчика».
2. «Загрузить распакованное расширение» → папка `extension/`.
3. Открыть `music.youtube.com`.

В панели настроек включить «YouTube Music (мост)».

Как это работает: content script на `music.youtube.com` читает
`navigator.mediaSession.metadata` (основной источник — переживает редизайны)
с откатом на DOM-селекторы плеер-бара, а позицию и длительность берёт из
`<video>`. Сокет держит фоновый service worker, а не content script: CSP
страницы блокирует исходящие соединения на localhost.

**Хрупкое место:** при редизайне `music.youtube.com` могут отвалиться
DOM-селекторы в `extension/content-script.js`. Чинить нужно там.

### Объединение

`now-playing.ts` отдаёт единый поток. Играющий источник важнее молчащего, при
равенстве — тот, от кого обновление пришло позже, поэтому переключаться между
Spotify и YT Music вручную не нужно. Позиция интерполируется между опросами.

## Текст песни

Источник — [lrclib.net](https://lrclib.net): бесплатно, без API-ключа. Поиск по
artist + title + duration, с откатом на `/api/search`. Поддерживается и обычный
LRC, и enhanced LRC с потаймингом по словам — тогда включается караоке-подсветка.
Текст не найден — просто не показываем.

Текст рисуется DOM'ом, а не на канвасе: так он остаётся резким на 4K и не
участвует в композиции слоёв. Текущая строка появляется через fade-in со
смещением вверх, предыдущая синхронно уходит.

Цвет берётся из текущей палитры (или задаётся вручную), размер, позиция и режим
настраиваются в панели.

Тексты песен — материал с авторским правом; проект рассчитан на личное
некоммерческое использование дома.

## Настройки и профили

Панель (`S`) покрывает чувствительность (отдельный гейн на energy, flux,
brightness, ZCR, порог удара, сглаживание), микс слоёв, генератор (авто/вручную,
Reshuffle, скорость морфинга, качество raymarch), палитру (готовые схемы и своя,
отдельно для мажора и минора), транзиенты, BPM вручную, обложку, текст песни.

Настройки сохраняются автоматически. Именованные профили и стартовые шаблоны
(«Рок-вечер», «Электроника», «Спокойный фон») — в разделе «Профили».

### Безопасность

Частота полноэкранных вспышек ограничена **3 Гц** и поднять её выше через UI
нельзя — это защита от фотосенситивной эпилепсии. Strobe, shake и glitch
отключаются по отдельности.

## Производительность

Цель — 60 fps на 1080p. Что для этого сделано:

- пиксельный размер холста ограничен `min(devicePixelRatio, 1.5)`;
- Voronoi считается в поле 168×94 и только 30 раз в секунду;
- metaballs рисуются в половинном разрешении, порог делается фильтром canvas;
- raymarch идёт в отдельный offscreen-канвас с масштабом разрешения, и
  compositor **сам снижает его**, если fps проседает ниже 50, возвращая обратно,
  когда появляется запас;
- если WebGL2 недоступен, raymarch просто исключается из пула.

Замер CPU-части (самое тяжёлое место без GPU — пересчёт поля Вороного):
**2 мс на пересчёт**, то есть около 6% одного ядра при 30 Гц.

## Дев-страницы

Обе доступны при `npm run dev` и в прод-сборку не попадают.

| Адрес | Зачем |
|---|---|
| `/dev/smoke.html` | гоняет каждый примитив по всем четырём секциям на синтетическом mood vector — проверка, что ничего не падает и что примитивы различимы |
| `/dev/smoke.html?only=voronoi&section=drop` | держит одну пару «примитив × секция» бесконечно — для разглядывания конкретного примитива |
| `/dev/audio-check.html` | подаёт в анализатор сигнал с известной тональностью и темпом — калибровка chroma, key и BPM без настоящего трека |

## Что проверено

Прогон в Chromium (WebGL — программный, поэтому абсолютные времена кадра там
не показательны):

- `/dev/smoke.html` — 1260 кадров, все 7 примитивов × 4 секции, ошибок нет;
- `/dev/audio-check.html` — A minor определяется как A minor, C major как
  C major, клик-трек 128 BPM определяется как 127.7 BPM;
- основная страница грузится без ошибок, панель строится целиком, горячие
  клавиши работают;
- уровни проверены замером средней яркости кадра на самой тяжёлой секции
  (`drop`, энергия 0.9): ни один примитив не выбивает в белое больше 3%
  кадра. Этот замер нашёл три реальных бага — неограниченное накопление
  свечения в raymarch, порог метаболлов, который применялся к каждому блобу
  по отдельности (и потому не давал слияния), и общее пересветление
  жанрового слоя при сложении.

**Не проверено вживую:** захват системного звука (нужен Windows с Chrome и
реальный выбор «Весь экран»), Spotify OAuth (нужен реальный Client ID),
мост YouTube Music (нужен Chrome с расширением и открытый music.youtube.com),
запрос к lrclib.net (нужен доступ в интернет из браузера), fps на настоящем GPU.
Пороги onset и веса рейтинга подобраны аналитически и почти наверняка потребуют
подгонки под конкретную фонотеку — для этого и нужны дебаг-оверлей и дев-страницы.
