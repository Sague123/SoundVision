# SoundVision v2

Аудио-реактивная светомузыка для телевизора. Браузерная вкладка на мини-ПК,
подключённом к ТВ по HDMI: слушает **системный звук** (что угодно — Spotify,
YouTube Music, плеер, браузер), строит генеративную картинку под жанр,
тональность и транзиенты и показывает синхронизированный текст песни.

Никаких виртуальных аудиокабелей и никаких фиксированных пресетов.

---

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:5173
```

Для прода:

```bash
npm run build        # tsc --noEmit + vite build → dist/
npm run preview      # раздать dist/ по сети
```

### Захват системного звука (Windows, Chrome/Edge)

Это единственный неочевидный шаг, и от него зависит вообще всё:

1. Нажать «Запустить визуализацию».
2. В окне выбора источника перейти на вкладку **«Весь экран»** и выбрать экран.
   Захват *отдельной вкладки* даёт звук только этой вкладки — системный звук
   так не получить.
3. Включить галочку **«Также предоставить доступ к системному аудио»**.

Разрешение выдаётся на сессию, поэтому старт-экран появляется при каждом
открытии страницы — это ограничение браузера, а не недоработка.

Видео-трек глушится сразу после получения разрешения: нужен только звук.

### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `S` | панель настроек |
| `F` | полный экран |
| `R` | Reshuffle — новая стартовая точка генератора для текущего трека |
| `D` | дебаг-оверлей с сырыми числами и графиками |
| `Esc` | закрыть панель |

Курсор прячется через 2.5 секунды без движения. Пока идёт визуализация,
запрашивается wake lock, чтобы экран не гас посреди вечера.

## Как это устроено

```
звук  →  mood vector  →  генератор  →  три слоя  →  compositor  →  экран
```

### Анализ звука (`src/audio/`)

FFT 2048, обновление на каждом кадре, экспоненциальное сглаживание с
настраиваемым коэффициентом.

| Файл | Что делает |
|---|---|
| `capture.ts` | `getDisplayMedia` + `AnalyserNode`, внятные ошибки на каждый отказ |
| `features.ts` | RMS, spectral flux/centroid, ZCR, onset с адаптивным порогом, тренд энергии → `section`, разбиение спектра на три полосы и **частотный профиль удара** |
| `chroma.ts` | chroma-вектор по 12 полутонам, тональность по Krumhansl-Schmuckler |
| `beat-tracker.ts` | BPM автокорреляцией огибающей onset-силы + фаза доли |
| `mood-vector.ts` | сборка всего в один объект на кадр |

Громкость нормализуется адаптивно (убывающий пик), поэтому тихий джаз и
закомпрессированное техно одинаково живые без ручного гейна.

Спектр делится на три полосы (до 180 Гц, до 2.2 кГц, выше) с **раздельной
нормализацией**: по абсолютной магнитуде хай-хэт всегда проигрывает бочке, и без
этого профиль любого удара был бы «низ». Из профиля удар классифицируется как
бас, снейр, хэт или широкополосный — и от этого зависит, какие эффекты сработают.

`section` (`buildup` / `drop` / `calm` / `steady`) считается из окна ~14 секунд:
короткое среднее против длинного плюс наклон, с гистерезисом, чтобы набор
примитивов не дёргался.

### Сцена (`src/render/scene.ts`)

Всё на экране — проявление одной физической сцены, а не набор независимых
фильтров. Музыка действует на пять связанных сущностей:

```
          ИМПУЛЬС (удар в музыке)
              |
   +----------+----------+---------+
   v          v          v         v
ВЕЩЕСТВО    СВЕТ      КАМЕРА    ПАМЯТЬ
(деформация)(вспышка)  (толчок)  (эхо)
```

| Сущность | Что это | Чем управляется |
|---|---|---|
| Вещество | из чего сделан мир | `noisiness`, `brightness`, `section` |
| Свет | освещает вещество: угол, интенсивность, температура | `key.mode`, `energy`, темп |
| Камера | наблюдатель внутри сцены | `bpm`, `section`, `energy` |
| Импульс | энергия удара, расходится волной | `onset`, `flux` |
| Память | сцена помнит прошлые кадры | `bpm` (эхо в ритме), `section` |

Ключевая связь: **один удар порождает согласованную реакцию всех сущностей
сразу**. Импульс рождается в конкретной точке кадра, и от неё же расходится
волна, которая физически расталкивает частицы flow field и коробит поверхность
в raymarch; свет вспыхивает; камера получает толчок в противоположную сторону;
память ставит в очередь повторы этого удара через 1/2 и 1/4 такта. Эхо —
полноценный импульс со всей той же реакцией, только слабее и комплементарного
цвета.

#### Агрегатное состояние вещества

Непрерывная ось, а не переключатель:

```
ТУМАН ──── ЖИДКОСТЬ ──── КРИСТАЛЛ ──── ПЛАЗМА
мягкое,    текучее,      грани,        искры,
рассеянное вязкое        отражения     свечение
```

Примитивы распределены по этой оси (flow field 0.05, L-система 0.26,
metaballs 0.36, Voronoi 0.66, cellular 0.74, калейдоскоп 0.78, raymarch 0.97),
и рейтинг уместности на 62% состоит из расстояния до текущей точки. То есть
набор на экране — прямое следствие того, из чего сейчас сделан мир, а не
отдельный независимый выбор. Ось двигают `noisiness`, `brightness` и `section`,
а идёт она туда медленнее всего остального: постоянная времени 1.6 с.

Жёсткость вещества становится резкостью форм, деформация от прошедших волн —
искажением пространства, память — длиной следов.

#### Импакт-эффекты

Десять эффектов, и все приходят из одного импульса. Что именно сработает,
решают **сила удара** и его **частотный профиль**:

| Эффект | Что делает | Когда |
|---|---|---|
| Screen shake | толчок камеры; низ бьёт по вертикали, верх даёт дрожь без оси | любой заметный удар |
| Shockwave | расширяющееся кольцо радиального искажения UV | бас-удар |
| Ripple | водная рябь из трёх затухающих колец | средний удар на жидком веществе |
| Punch zoom | резкий наезд с упругим возвратом (пружина с затуханием) | дроп |
| Lens pulse | кратковременная бочка или подушка | сильный удар; бас выдавливает наружу, верх втягивает |
| Roll kick | резкий крен с возвратом | снейр |
| Compression | сцена сжимается по вертикали и растягивается по горизонтали | кик |
| Chromatic burst | RGB-каналы разлетаются от центра и сходятся | пик силы |
| Slice displacement | горизонтальные блоки уезжают в сторону | резкий flux |
| Pressure wave | волна физически расталкивает частицы | дроп |

Комбинирование — лестница по силе: слабый удар даёт только толчок камеры,
заметный добавляет волну или рябь, сильный — линзу и разлёт каналов, дроп
запускает почти всё сразу. Поэтому нарастание читается как нарастание, а не как
бинарное «есть удар / нет удара».

#### Деформации вещества

Постоянно активны на низком уровне и усиливаются на пиках — без этого картинка
встаёт колом между ударами.

- **Domain warping** — шум гнёт само координатное пространство; самый ценный приём;
- **Twist** — закручивание вокруг центра, скорость от темпа;
- **Wave** — синусоидальное смещение по осям;
- **Turbulence** — мелкие локальные завихрения поверх крупного варпа;
- **Melt** — вертикальное стекание; включается только на медленных минорных местах;
- **Fold** — зеркальные складки пространства; живут на кристаллической части оси.

Всё это плюс UV-эффекты из таблицы выше, память кадра и свет делается **одним
конвейером на GPU** (`post-pass.ts`): сведённый кадр попадает в видеопамять
один раз и возвращается на экран один раз, без промежуточных копий через
канвасы. Порядок: варп → яркостный срез → два прохода размытия → сведение
света. Так искажение ведёт себя как свойство пространства сцены, а не как
настройка каждой фигуры, и стоит фиксированную цену независимо от числа
примитивов. Раньше глитч считался на CPU по пикселям — этот код заменён
шейдерными chromatic burst и slice displacement.

Обратная связь кадра идёт **ping-pong между двумя FBO**: варп пишет в один
буфер и читает второй, а на следующем кадре они меняются местами. Копировать
кадр не нужно вовсе.

Завершает цепочку **расширенный тон-маппинг Рейнхарда** — глобально, а не
точечно. Обычный Рейнхард никогда не доводит до единицы и делает кадр вялым;
расширенный отображает точку белого ровно в 1 и сохраняет яркие места. Точка
белого едет за измеренной средней яркостью кадра.

**Уровни качества** — низкое, среднее, высокое. Уровень меняет согласованно
разрешение буферов свечения, число проходов размытия, выборки объёмных лучей,
контровой свет и разрешение raymarch. Автоснижение идёт по лестнице: высокое →
среднее → низкое → конвейер снят целиком. Ручной выбор — это потолок: авто
может опустить уровень, но не поднять выше него. Возвращается уровень неохотно
(шесть проверок запаса против двух на снижение), чтобы не дёргаться туда-сюда.

Одна честная оговорка по §11: слои рисуются в 2D-канвасы и попадают в цепочку
одной загрузкой текстуры за кадр, а не рендерятся прямо в FBO. Рендер примитивов
целиком в WebGL — это переписывание всех семи примитивов, а выигрыш был бы в
одной загрузке кадра. Свойство, ради которого пункт написан, выполняется:
пост-обработка идёт над текстурой, а не над экраном.

Конвейер пропускается целиком, когда делать нечего, и автоматически снимается,
если уровень уже низкий, а fps всё равно не вытягивает: лучше без деформаций и
света, но плавно.

Посмотреть каждое искажение отдельно можно на `/dev/impact-check.html`.

#### Камера

Камера живая всегда: даже в полной тишине идёт медленный дрейф по шуму, иначе
картинка ощущается обоями.

- **Idle drift** — низкочастотный шум по позиции, всегда включён;
- **Orbit** — облёт центра, скорость привязана к фразе, а не к биту;
- **Dolly** — движение вперёд/назад; плотное вещество тянет вперёд, разреженное
  назад. Само по себе почти не видно — туннель из него делает обратная связь
  кадра, которой оно задаёт направление;
- **Roll** — крен, осциллирует в темпе;
- **FOV breathing** — поле зрения сужается на билд-апе (0.78) и резко
  раскрывается на дропе (1.36). Вниз тянется медленно, вверх — быстро, поэтому
  раскрытие читается как выдох;
- **Look-at wander** — точка интереса блуждает по собственному шуму, и наезд с
  креном идут вокруг неё, а не вокруг центра кадра;
- **Cut** — резкая смена ракурса на границе части: сбрасываются фазы дрейфа,
  орбиты и точки интереса. Только на дропе и возврате в затишье, не чаще раза
  в 16 секунд, отключается в настройках.

#### Свет

Отдельный проход по сведённому кадру:

- **Bloom с адаптивным порогом** — порог держится выше средней яркости кадра
  (она замеряется по копии 16×9 раз в шесть кадров), поэтому светится то, что
  выделяется, а не картинка целиком. Плюс мягкое колено вместо ступеньки и
  мягкое сжатие на выходе вместо обрезания;
- **Volumetric rays** — радиальное накопление яркой части к источнику;
- **Rim light** — градиент яркости вместо нормали, светится та сторона
  силуэта, что обращена к источнику;
- **Lens flare** — три призрака вдоль линии «источник — центр» плюс ядро,
  только на пиковых ударах и не от эха;
- **Exposure pumping** — экспозиция дышит на долю. Размах около 0.18 — это
  дыхание, а не строб, и лимита частоты ему не нужно;
- **Dynamic vignette** — поджимается на билд-апе (0.89), раскрывается на
  дропе (0.12);
- **Light position** — источник ходит за доминирующей полосой: бас опускает
  его вниз, верх поднимает вверх;
- **Strobe** — лимит 3 Гц, отдельный тумблер, **по умолчанию выключен**.

#### Частицы

Девять типов, и все живут в **одном общем поле потока** — том же, что несёт
линии фона. Это и делает их частью сцены, а не слоем поверх неё.

| Тип | Поведение | Когда активен |
|---|---|---|
| Sparks | искры с гравитацией, короткий след вдоль скорости | резкие атаки, шумность |
| Dust | медленная взвесь, видна против источника света | затишье |
| Ribbons | ленты с хвостом в девять точек вдоль потока | плавное и мелодичное |
| Shards | осколки с вращением, разлетаются от удара | высокая шумность |
| Bokeh | мягкие кружки с провалом в центре | мажор, спокойное |
| Swarm | стая: сплочённость и выравнивание, рассыпается вблизи центра | ритмичное, средняя энергия |
| Embers | угли всплывают и мерцают | минор, глухое |
| Streaks | вертикальные полосы | плотный верх |
| Petals | лепестки качаются при падении | мажорные пики |

Плотность, скорость и время жизни идут от энергии. Активный набор выбирает тот
же непрерывный рейтинг уместности, что и примитивы, плюс смещение от seed'а
трека. Искры и осколки рождаются пачкой в момент удара, остальные — постоянным
потоком.

#### Бюджет интенсивности и амплитуда движения

Две ручки против двух рисков — каши и укачивания.

**Бюджет** ограничивает суммарную активность. Четыре группы (деформации, удары,
память, движение) заявляют свою нагрузку и свою уместность; если сумма не
влезает в лимит, каждая получает долю пропорционально уместности, но не больше,
чем просила. Поэтому в момент удара ужимаются в первую очередь деформации, а не
сам удар. Значения правятся на месте, дальше по конвейеру идёт уже ужатая сцена.

**Амплитуда движения** — общий множитель для камеры, тряски, толчков и
деформаций. Применяется один раз, ко всему выходу камеры сразу, включая дрейф и
орбиту: именно они дают основную часть движения, и гасить только толчки
бесполезно. Есть готовый профиль «Спокойная камера».

#### Память и эхо

- **Motion trails** — частичная очистка кадра, длина следа от секции;
- **Frame feedback** — прошлый кадр подмешивается со сдвигом, масштабом и
  поворотом; отсюда туннели и спирали. Предохранитель принципиальный: берётся
  **максимум**, а не сумма, а прошлый кадр предварительно гасится. Максимум
  затухающей последовательности не может превысить самый яркий кадр в истории,
  поэтому обратная связь не расходится в белое даже теоретически. Доля сверх
  того ограничена потолком 0.88;
- **Ритмическое эхо** — удар повторяется в долях такта. Рисунок выбирает seed
  трека: прямой (1/2, 1/4), пунктирный (3/8, 3/4) или плотный (1/4, 1/2, 3/4);
- **Ghost impulses** — призраки прошлых ударов гаснут несколько секунд;
- **Temporal smear** — размазывание на дропе, взвешенное среднее с прошлым
  кадром (сжимающая операция, ярче исходника стать не может).

### Генеративная система (`src/render/`)

Вместо фиксированных пресетов — пул примитивов с непрерывными параметрами:

**Примитивы:** flow field (частицы в поле симплекс-шума), metaballs
(blur + contrast вместо marching squares), Voronoi (поле расстояний в низком
разрешении, 30 Гц), cellular automata (5 наборов правил, шаг привязан к темпу),
L-система (фрактальное ветвление), raymarch (WebGL2, SDF).
**Калейдоскоп** — не рисующий примитив, а модификатор: отражает N-угольной
симметрией всё, что уже нарисовано в жанровом слое.

Что делает картинку разной:

- **Seed трека** — хэш `artist + title` задаёт пул примитивов, порядок
  симметрии, сдвиг палитры, скорость морфинга и смещение рейтинга каждого
  примитива. Трек узнаваем при повторном прослушивании, но это не клип.
  Два разных трека с похожим mood vector выглядят по-разному именно из-за
  смещения рейтинга.
- **Рейтинг уместности** — каждый примитив непрерывно оценивается по текущему
  настроению; активны верхние N, где N зависит от секции (затишье — 1, дроп — 3).
- **Морфинг** — веса едут к цели экспоненциально, никаких переключений.
  Калейдоскоп вплывает через `smoothstep`, а не включается щелчком.

### Слои

1. **База** (`layer-base.ts`) — палитра и фон от тональности и энергии, один
   медленный примитив подложкой, виньетка, опционально размытая обложка.
2. **Жанр** (`layer-genre.ts`) — активный набор примитивов со следами
   (длина следа — от энергии) и калейдоскоп поверх.
3. **Транзиенты** (`layer-transient.ts`) — particle burst, shockwave,
   screen shake, strobe flash и глитч (RGB-сплит + сдвиг блоков по сведённому
   кадру).

`compositor.ts` сводит их, применяет тряску с оверскейлом (чтобы не открывались
чёрные поля), накладывает глитч и держит fps.

### Палитра: OKLCH

Вся работа с цветом идёт в OKLCH, конвертация в sRGB — только на выходе.
Интерполяция в RGB или HSL проходит через грязно-серые промежуточные цвета, а
одинаковая светлота у разных оттенков выглядит по-разному яркой. В OKLab этого
нет. Выход за охват sRGB чинится снижением хромы делением отрезка при
сохранении L и H — цвет теряет насыщенность, но не уезжает в другой оттенок.

Привязка к музыке:

| Параметр | Источник | Правило |
|---|---|---|
| Оттенок | `key.tonic` | 12 нот по **квинтовому кругу**, не хроматически: позиция ноты `n` равна `(n * 7) mod 12`. До и соль — соседние цвета, поэтому модуляция внутри трека даёт сдвиг, а не скачок через полкруга |
| Температура | `key.mode` | мажор тянет к тёплому полюсу (янтарь, 75°), минор — к холодному (индиго, 252°), с весом от уверенности в тональности |
| Хрома | `brightness` | яркий звук — высокая хрома, глухой — приглушённая |
| Светлота | `energy` | громче → **выше контраст** между фоном и формами: формы светлее, фон темнее. Не «ярче всё» — иначе на дропе кадр просто выцветает |
| Разброс | `section` | затишье 0.34, ровно 0.62, билд-ап 0.8, дроп 1.0. На затишье комплементарная схема сама собой сжимается в аналоговую |
| Якорь | обложка | 2–3 доминантных цвета обложки (кластеризация прямо в OKLCH, взвешенная хромой) подмешиваются с настраиваемым весом |

**Гармонические схемы** выбираются seed'ом трека: аналоговая, комплементарная,
сплит-комплементарная, триадная, монохромная с акцентом. Из-за этого два трека
в одной тональности всё равно различаются по цветовому характеру.

**Динамика:**
- *дыхание* — медленная осцилляция хромы по такту и светлоты по фразе
  (не по биту: на бите это читалось бы как мигание);
- *цветовое эхо* — эхо-импульс красится комплементарным цветом и расходится
  волной, гаснув;
- *миграция* — смена тональности или секции переходит за ~1.4 секунды, а не
  мгновенно.

Посмотреть всю раскладку можно на `/dev/palette-check.html`.

## Обложка трека

### Spotify

1. Завести приложение в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. В Redirect URIs указать **адрес этой страницы** (например
   `http://localhost:5173/`) — ровно тот, что показан в адресной строке.
3. В панели настроек: «Обложка и источники» → «Подключить Spotify», вставить
   Client ID.

Авторизация — Authorization Code + PKCE (client secret в браузере хранить негде),
токены в localStorage, поллинг `/me/player/currently-playing` раз в 4 секунды.
Оттуда же берутся `progress_ms` и `duration_ms` для текста песни.

### YouTube Music

Нужны две части — мост и расширение:

```bash
npm run bridge       # ws://127.0.0.1:8787, слушает только localhost
```

Расширение (`extension/`) ставится как unpacked, публикация в Chrome Web Store
не нужна:

1. `chrome://extensions` → включить «Режим разработчика».
2. «Загрузить распакованное расширение» → папка `extension/`.
3. Открыть `music.youtube.com`.

В панели настроек включить «YouTube Music (мост)».

Как это работает: content script на `music.youtube.com` читает
`navigator.mediaSession.metadata` (основной источник — переживает редизайны)
с откатом на DOM-селекторы плеер-бара, а позицию и длительность берёт из
`<video>`. Сокет держит фоновый service worker, а не content script: CSP
страницы блокирует исходящие соединения на localhost.

**Хрупкое место:** при редизайне `music.youtube.com` могут отвалиться
DOM-селекторы в `extension/content-script.js`. Чинить нужно там.

### Объединение

`now-playing.ts` отдаёт единый поток. Играющий источник важнее молчащего, при
равенстве — тот, от кого обновление пришло позже, поэтому переключаться между
Spotify и YT Music вручную не нужно. Позиция интерполируется между опросами.

## Текст песни

Источник — [lrclib.net](https://lrclib.net): бесплатно, без API-ключа. Поиск по
artist + title + duration, с откатом на `/api/search`. Поддерживается и обычный
LRC, и enhanced LRC с потаймингом по словам — тогда включается караоке-подсветка.
Текст не найден — просто не показываем.

Текст рисуется DOM'ом, а не на канвасе: так он остаётся резким на 4K, к нему
применимы `backdrop-filter` и variable fonts, и он не участвует в композиции
слоёв.

**Схемы появления** выбираются по характеру трека или фиксируются в настройках:
мягкая (размытие 16px → 0 вместе с подъёмом и едва заметным масштабом), резкая
(маска слева направо, для агрессивного материала), побуквенная (задержка 18 мс
между буквами) и проявление. Уход — размытие со сдвигом вверх либо растворение.

**Караоке** заливает текущее слово слева направо. Сделано двумя наложенными
слоями: приглушённая основа и яркая копия, обрезанная `clip-path`. Через
`background-clip: text` так нельзя — см. ниже, это стоило отдельного бага.

**Реакция на музыку**: вес variable font ведётся энергией, трекинг слегка
расширяется на пиках, на сильный удар строка смещается синхронно с тряской
сцены, но с заметно меньшей амплитудой — прыгающий текст читать невозможно.

**Читаемость.** Подложка с `backdrop-filter` есть всегда, и её цвет всегда
противоположен цвету текста: светлый текст получает тёмную плашку и наоборот.
Цвет текста подбирается от **измеренной средней яркости кадра** — белого текста
на светлом кадре не будет. Ореол помогает только светлому тексту; вокруг тёмного
он почти снимается, потому что светящийся контур вокруг тёмной буквы съедает
контраст. Режим «максимальная читаемость» уплотняет подложку для тех, кто
реально подпевает.

**Гарнитуры** (все variable, все с подтверждённой кириллицей):

| Характер | Гарнитура | Почему |
|---|---|---|
| Рок, агрессия | Oswald | узкий, плотный, хорош капсом |
| Электроника | Unbounded | геометричный, холодный, широкий трекинг |
| Мажор, лёгкое | Inter | нейтральный, чистый |
| Минор, меланхолия | Cormorant italic | контрастная антиква, драматичная |
| Эксперимент, глитч | JetBrains Mono | моноширинный, технический |

Кириллица не берётся на веру: каждая гарнитура проверяется в рантайме
измерением ширины кириллической строки против двух независимых запасных
шрифтов. Если совпало — значит гарнитура не применилась, и она исключается из
автовыбора. Проверка **отбраковала Archivo** из исходного списка: кириллицы в
нём нет. Его место занял Oswald.

Размер, позиция (низ/центр/верх), режим, гарнитура, схема появления, читаемость
и реакция на музыку настраиваются в панели.

## Карточка трека

Появляется при смене трека, держится семь секунд и уходит: слева миниатюра
обложки, справа название крупно и артист мельче. Вход — выезд слева с
размытием, уход — растворение со сдвигом. Если текст песни стоит внизу,
карточка сама уезжает наверх, чтобы не драться за один угол.

Режимы: показывать при смене трека, держать всегда мелко в углу (там же, но
меньше и тише), не показывать. Отдельно — тонкая линия прогресса трека по
нижней кромке экрана.

Тексты песен — материал с авторским правом; проект рассчитан на личное
некоммерческое использование дома.

## Настройки и профили

Панель (`S`) покрывает чувствительность (отдельный гейн на energy, flux,
brightness, ZCR, порог удара, сглаживание), микс слоёв, генератор (авто/вручную,
Reshuffle, скорость морфинга, качество raymarch), палитру (гармоническая схема
или авто от seed, сдвиг оттенка, хрома, светлота форм, сила температуры лада,
вес якоря обложки), камеру (амплитуда и склейки), десять импакт-эффектов по
отдельности, деформации вещества, девять типов частиц, свет (свечение, лучи,
контровой, блики, экспозиция, виньетка), память сцены (обратная связь,
размазывание, призраки), BPM вручную, обложку, текст песни.

Оттенок палитры вручную не задаётся: он идёт от тоники. Ручка «сдвиг оттенка»
поворачивает всю систему целиком, сохраняя привязку к квинтовому кругу.

Настройки сохраняются автоматически. Именованные профили и стартовые шаблоны
(«Рок-вечер», «Электроника», «Спокойный фон») — в разделе «Профили».

### Безопасность

Частота полноэкранных вспышек ограничена **3 Гц** и поднять её выше через UI
нельзя — это защита от фотосенситивной эпилепсии. Strobe, shake и glitch
отключаются по отдельности.

---

## Производительность

Цель — 60 fps на 1080p. Что для этого сделано:

- пиксельный размер холста ограничен `min(devicePixelRatio, 1.5)`;
- Voronoi считается в поле 168×94 и только 30 раз в секунду;
- metaballs рисуются в половинном разрешении, порог делается фильтром canvas;
- raymarch идёт в отдельный offscreen-канвас с масштабом разрешения, и
  compositor **сам снижает его**, если fps проседает ниже 50, возвращая обратно,
  когда появляется запас;
- если WebGL2 недоступен, raymarch просто исключается из пула.

Замер CPU-части (самое тяжёлое место без GPU — пересчёт поля Вороного):
**2 мс на пересчёт**, то есть около 6% одного ядра при 30 Гц.

## Что проверено

Прогон в Chromium (WebGL — программный, поэтому абсолютные времена кадра там
не показательны):

- `/dev/smoke.html` — 1260 кадров, все 7 примитивов × 4 секции, ошибок нет;
- `/dev/audio-check.html` — A minor определяется как A minor, C major как
  C major, клик-трек 128 BPM определяется как 127.7 BPM;
- `npm run check` — 52 проверки: эхо приходит ровно через 500 и 1000 мс при
  120 BPM (четверть и половина такта), ось вещества не прыгает больше 0.009 за
  кадр при резкой смене звука, до/соль и до/фа расходятся на 30°, до/фа-диез на
  180°, все 12 тоник дают разные оттенки, смена тональности сдвигает палитру на
  5° в первом кадре и доезжает за 1.5 с, а на оси вещества в тишине побеждает
  flow field и на шумном пике — raymarch; бочка/снейр/хэт различаются по профилю,
  слабый удар не запускает тяжёлые эффекты, а число одновременных эффектов растёт
  от 0 на слабом ударе до 5 на дропе; рябь появляется на жидком веществе и не
  появляется на тумане; бас трясёт по вертикали, верх — во все стороны; наезд
  возвращается упруго; деформации ненулевые в тишине и растут на пике, а стекание
  включается только на медленном миноре; поле зрения сужается до 0.78 на
  билд-апе и раскрывается до 1.36 на дропе; склейки идут не чаще раза в 18
  секунд и полностью выключаются настройкой; бас опускает источник света до
  y=0.77, верх поднимает до y=0.23; виньетка поджимается до 0.89 и раскрывается
  до 0.12; экспозиция дышит с размахом 0.18, то есть остаётся дыханием; набор
  частиц меняется по настроению, а плотность меняет их количество впятеро;
  бюджет ужимает эффекты и удерживает суммарную нагрузку в лимите, причём удары
  в момент удара ужимаются слабее деформаций; мастер амплитуды гасит движение
  камеры втрое;
- `/dev/impact-check.html` — все 13 искажений отрисованы проходом варпа и визуально
  различимы; проверка нашла два бага: `active` оказалось зарезервированным словом
  GLSL ES 3.00 (шейдер молча не компилировался, и варп отключался), и у lens pulse
  был перепутан знак — «бочка» вела себя как подушка;
- текст: кириллица подтверждена у всех пяти гарнитур измерением (Archivo из
  исходного списка отбракован — кириллицы нет). Контраст меряется **по реальным
  пикселям кадра**, а не по задуманному цвету: ядро глифа против моды подложки
  даёт 10.9:1 в обычном режиме и 16.5:1 в режиме максимальной читаемости, оба
  выше AAA. Именно этот замер нашёл, что заливка текста не рисовалась вовсе:
  при `background-clip: text` глиф — это фон, а фон красится до теней, и белая
  обводка ложилась поверх. На экране было 1.5:1 там, где проверка по цвету
  рапортовала 6.9:1;
- цвет: OKLCH сверен с эталонными значениями чистых цветов sRGB (отклонение 0)
  и на 4096 случайных цветах в круговом преобразовании (отклонение 0);
- свет: со всем включённым свечением выжигания нет — доля пикселей в белом
  0.0% на всех семи примитивах на секции `drop`;
- камера: чёрная кайма по краю кадра 0.0% на всех примитивах — оверскейл
  накрывает крен и сдвиг;
- основная страница грузится без ошибок, панель строится целиком, горячие
  клавиши работают;
- уровни проверены замером средней яркости кадра на самой тяжёлой секции
  (`drop`, энергия 0.9): ни один примитив не выбивает в белое больше 3%
  кадра. Этот замер нашёл три реальных бага — неограниченное накопление
  свечения в raymarch, порог метаболлов, который применялся к каждому блобу
  по отдельности (и потому не давал слияния), и общее пересветление
  жанрового слоя при сложении.

**Риски, о которых стоит помнить.** Все эффекты на полную одновременно дают
кашу — для этого бюджет интенсивности. Камера вместе с деформациями и тряской
укачивает — для этого мастер амплитуды и профиль «Спокойная камера». Каждый
проход конвейера стоит кадров — для этого уровни качества с автоснижением.

**Не проверено вживую:** захват системного звука (нужен Windows с Chrome и
реальный выбор «Весь экран»), Spotify OAuth (нужен реальный Client ID),
мост YouTube Music (нужен Chrome с расширением и открытый music.youtube.com),
запрос к lrclib.net (нужен доступ в интернет из браузера), fps на настоящем GPU.
Пороги onset и веса рейтинга подобраны аналитически и почти наверняка потребуют
подгонки под конкретную фонотеку — для этого и нужны дебаг-оверлей и дев-страницы.
